# Challenges & Notes

Quick dev notes on the errors and gotchas hit while building and testing this project, and how we solved each one.

- **AWS Account swap:** Started setup in a personal account (`eu-north-1`), then switched to the Udacity sandbox in `us-east-1`. Had to update credentials in `.env` and recreate all the resources (Lambdas, API Gateway, Knowledge Base, Memory, Gateway) in the sandbox.
- **Missing `zip` on Windows:** Running `agentcore deploy` gave an error because Windows PowerShell doesn't have a built-in `zip` CLI command. Downloaded `zip.exe` to `C:\Users\harve\` and prepended it to `$env:PATH` so the deployment script could bundle the project archive.
- **`pywin32` build failure:** The deploy failed during Linux cross-compilation because `pywin32` was dragged in as a Windows dependency and has no Linux ARM64 wheels. Fixed it by adding an override in `pyproject.toml` under `[tool.uv]` to only install `pywin32` on Windows systems.
- **Slow initial dependency build:** First deploy took 5+ minutes downloading ~100+ Linux ARM64 wheels (like `playwright` and `cryptography`) without a progress bar. Once cached locally in `.bedrock_agentcore/`, subsequent deploys only take about 30 seconds.
- **Terminal emoji crash (`charmap` error):** `agentcore configure` crashed on Windows because the default `cp1252` terminal encoding can't print emojis (❌, ✅, 🚀) output by the CLI's `rich` library. Fixed by setting `$env:PYTHONIOENCODING="utf-8"` and `$env:PYTHONUTF8="1"`.
- **Deploying to wrong account (`maxAgents` quota):** The deploy CLI was picking up the default `~/.aws/credentials` (personal account with 0 agent quota) instead of the sandbox account. Exported the sandbox session keys directly in the PowerShell session before configuring and deploying.
- **Memory strategy key mismatch:** Calling `get_memory_strategies()` was returning strategy types under the key `'type'` rather than `'strategyType'`. Used a fallback `s.get("type") or s.get("strategyType")` in `get_namespaces()` to handle either format safely.
- **`MCPClient` argument name:** The starter comments said `tools_prefix="gateway"`, but the installed Strands SDK version uses `prefix="gateway"`. Checking the function signature helped spot and fix the parameter name.
- **Async `await` on synchronous `client.start()`:** Calling `await client.start()` threw an error because `start()` in the Strands SDK is actually a synchronous method, not a coroutine. Removed `await` so it starts normally.
- **Bedrock memory extraction delay:** In multi-session testing, asking the agent about user details right after introducing ourselves resulted in it forgetting. Bedrock processes semantic facts and preferences in a background LLM pipeline that takes about 60-90 seconds to index. Waiting a minute before the follow-up query solved it, and it remembered the customer's name and concise preference.
- **`code_session` context manager usage:** `code_session(REGION)` is a Python context manager and must be wrapped in `with code_session(...) as session:`. Calling it without `with` threw an exception and dropped into a fallback. Also made sure the fallback has the full loyalty formula so points redemption always works even if the cloud interpreter is offline or throttled.
- **Agent doing mental math instead of calling the tool:** The LLM tried to guess the loyalty discount calculation on its own rather than running the tool. Added strict rules in the tool docstring and system prompt telling the agent that loyalty math must always be executed through `calculate_loyalty_discount` and reported with exact numbers.
- **Browser automation action schema and workflow requirement:** When testing the browser tool, the agent reported a system permission error when trying to navigate to a URL directly. In reality, the tool had failed Pydantic validation because the payload requires an `"action"` envelope: `browser_input={"action": {"type": ...}}`. Furthermore, browsing is a sequential process: initializing a session first via `init_session`, navigating via `navigate`, and retrieving page content or title using `evaluate` with the `script` parameter (`document.title`). Clarifying this exact action sequence and schema in the system prompt solved the validation error and enabled browser automation.
- **OneDrive filesystem hardlink error (`os error 396`):** When `uv` downloads and packages dependencies in a OneDrive-synced folder, attempting to hardlink cached files fails with *"The cloud operation cannot be performed on a file with incompatible hardlinks"*. Setting `$env:UV_LINK_MODE="copy"` tells `uv` to use file copying instead of hardlinks, avoiding filesystem sync conflicts.

- **Browser tool failed in the cloud (Permission denied on playwright's node):** I zip the code on Windows, so the Linux file permissions got lost and the browser couldn't start. Locally it worked fine, which is how I knew it was a packaging issue. Fixed by adding a small startup step in main.py that copies node to /tmp, makes it executable and points Playwright to it.
